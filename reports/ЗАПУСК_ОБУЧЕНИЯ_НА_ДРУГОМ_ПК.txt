ЗАПУСК ОБУЧЕНИЯ НА ДРУГОМ ПК — WINDOWS
Дата: 26.11.2026

Инструкция составлена Kin по текущим скриптам проекта.
Это текстовая инструкция, не исполняемый файл. Команды вводятся по одной.
Полное обучение на другом ПК ещё не проверено. Здесь data/ пуста.

ВАЖНО
- Работайте В ОТДЕЛЬНОЙ КОПИИ проекта. Обучение и экспорт перезаписывают
  models/weights_v2.joblib и models/weights_v2_numpy.joblib.
  Эксперименты перезаписывают отчёты, а train_v2.py — predictions/ на my_test.
- Не удаляйте исходную копию до сравнения новых и старых результатов.
- Основное обучение — sklearn на процессоре. Видеокарта, torch и
  torch-geometric для него не нужны. Установленный GPU его не ускоряет.
- Возобновления прерванного обучения нет: повторная команда начинает заново.
- Нет измеренных требований к памяти и времени. Для 100 000 опытов разумно
  планировать 16–32 ГБ ОЗУ и запас места под CSV/копии, но это рекомендация,
  не подтверждённый минимум. Не запускайте все эксперименты одновременно.

1. ЧТО ПЕРЕНЕСТИ

Скопируйте целиком папку HaKaToN в удобное место, например C:\Projects\HaKaToN.
Не переносите .venv*, __pycache__: окружение создаётся заново.
Сохраните структуру src/, scripts/, models/, reports/, tests/, my_test/,
predictions/, predictions_check/, requirements.txt, requirements-inference.txt
и baseline_solution.py. Архив и материалы тоже можно оставить.

Отдельно найдите ОРИГИНАЛЬНЫЕ обучающие файлы и положите их сюда:
  HaKaToN\data\train_nodes_34_100000.csv
  HaKaToN\data\train_lines_34_100000.csv

Сейчас этих CSV в проекте нет. Без них обучение невозможно.
Не подменяйте их файлами my_test/nodes.csv и my_test/lines.csv.
Скрипты ожидают именно указанные имена, без дополнительного расширения .csv.csv.
Обычный формат — CSV с запятыми, десятичной точкой, читаемый pandas.read_csv.

Нужные столбцы nodes:
  ID_опыта, Номер, U_ном, P_н, Q_н, P_г, V, Delta, regime_valid
Нужные столбцы lines для полного обучения и оценки:
  ID_опыта, Номер, N_s, N_e, type, R, X, B, Kt, I_max, I_доп, I_zarg

Один опыт исходной сети: 35 узлов, включая балансирующий 999, и 80 линий.
Ключ (ID_опыта, Номер) уникален в каждой таблице; наборы ID совпадают.
regime_valid должен быть 0 или 1 и одинаковым у всех узлов одного опыта.
Для обучения нужны оба класса и достаточно валидных опытов с целями.
Не переименовывайте заголовки в русские аналоги: обучающий загрузчик,
в отличие от основного CLI, не нормализует псевдонимы.
До обучения проверьте NaN/inf, дубликаты, пропуски узлов/линий и цели.
Не заменяйте отсутствующую разметку нулями ради запуска.

2. PYTHON И ТЕРМИНАЛ

Установите 64-битный Python 3.12 с официального сайта python.org,
если его ещё нет. Нужен также Python Launcher (команда py).
Python из ярлыка Microsoft Store может не быть настоящей установленной средой.

Откройте cmd.exe, НЕ PowerShell. Все команды ниже рассчитаны на cmd.
Перейдите в перенесённую папку. Путь ниже — ПРИМЕР, замените на свой:

cd /d "C:\Projects\HaKaToN"
py -3.12 --version
dir baseline_solution.py
dir data\train_nodes_34_100000.csv
dir data\train_lines_34_100000.csv

Ожидается Python 3.12.x и наличие трёх файлов.
Если py не найден, проверьте установку Launcher или используйте полный путь
к python.exe нужной версии при создании окружения.

3. ОКРУЖЕНИЕ И ЗАВИСИМОСТИ

py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m pip check
.venv\Scripts\python.exe --version
.venv\Scripts\python.exe -m pip show numpy pandas scikit-learn joblib
.venv\Scripts\python.exe -m pip freeze > reports\environment_training.txt

Активация окружения не нужна: всегда вызывается его собственный python.exe.
Для установки пакетов нужен интернет; дальнейшее обучение работает локально.
requirements.txt не фиксирует версии. Сохранённый environment_training.txt
нужен для повторения именно вашего окружения и переносится вместе с весами.
На следующем ПК ту же среду можно восстановить в новом окружении командой:
  .venv\Scripts\python.exe -m pip install -r reports\environment_training.txt
при совместимых ОС и версии Python.

При подготовке документа тесты прошли на Python 3.12.10 с numpy 2.5.4,
pandas 3.1.0, scikit-learn 1.9.1, joblib 1.6.0. Полное обучение на этих
версиях не выполнялось; одинаковые численные результаты не обещаются.
Исторические sklearn-веса создавались в другой среде (в отчёте sklearn 1.7.2).
Не загружайте старый sklearn-бандл в новой версии для продолжения обучения:
команда train_v2.py обучает новый с нуля, а экспорт запускается сразу после
неё в ТОМ ЖЕ окружении. Готовые numpy-веса sklearn не импортируют.

4. ПРОВЕРКА ДО ОБУЧЕНИЯ (НА ИСХОДНЫХ ВЕСАХ)

.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe -O -m unittest discover -s tests -v
.venv\Scripts\python.exe -m compileall -q baseline_solution.py src scripts tests
.venv\Scripts\python.exe scripts\train_v2.py --help

Ожидается 21 тест и OK в каждом режиме; compileall без ошибок.
Тесты включают реальный запуск на поставляемых numpy-весах. Обучающие CSV
для этих тестов не нужны. Исправьте ошибки до длительных запусков.

5. ОЦЕНКА КАЧЕСТВА ДО ФИНАЛЬНОГО ОБУЧЕНИЯ

Рекомендуемая команда (несколько обучений; может работать долго):

.venv\Scripts\python.exe -u scripts\exp_stage4.py

Результат: reports/stage4_results.json.
Проверяются seed 42/7/2024, блоки по ID и экстраполяция по нагрузке.
Смотрите F1/confusion, число валидных в тесте, ошибки по узлам и квинтилям,
regression_conditional и regression_submitted. Последнее учитывает обнуление
по предсказанному флагу. Обе регрессии считаются на истинно валидных опытах.
null означает неопределённую метрику, а НЕ идеальный результат.
Файл пишется по мере прогонов: наличие JSON ещё не означает завершение всех
пяти запусков; успешный конец сопровождается "3-seed summary:".
Этот скрипт оценивает MEDIUM + HGB, а не точную финальную numpy-модель.

Необязательно, для детальной диагностики AFTER и параллельных линий:
.venv\Scripts\python.exe -u scripts\exp_stage1.py
Результат: reports/stage1_results.json. Регрессия этого этапа условная,
без обнуления по предсказанному флагу; это не оценка всей конечной выдачи.

6. ФИНАЛЬНОЕ ОБУЧЕНИЕ

Запускайте после проверки данных и сохранения исходной копии проекта:

.venv\Scripts\python.exe -u scripts\train_v2.py --config after --seed 42

Ожидаемые сообщения: число опытов, обучение V/Delta/Izarg и "Сохранено:".
Результат: models/weights_v2.joblib.
Скрипт использует все опыты для финального пайплайна; регрессоры обучаются
по валидным, early stopping оставляет внутреннюю проверочную часть.
Такое обучение само по себе НЕ даёт независимую оценку качества.

Если нужен более короткий пробный прогон, можно использовать --config medium,
но это другая модель, а не финальный AFTER. Он тоже перезаписывает файл весов.
Параметр --out есть, но экспортёр читает строго models/weights_v2.joblib:
для штатной цепочки не меняйте --out.

После обучения predictions/ может содержать ДЕМО на my_test без обнуления
невалидных режимов. НЕ используйте эти CSV как окончательную выдачу.

7. ЭКСПОРТ В NUMPY — ОБЯЗАТЕЛЬНО ПОСЛЕ ОБУЧЕНИЯ

.venv\Scripts\python.exe -u scripts\export_numpy_bundle.py

Результат: models/weights_v2_numpy.joblib.
Экспортёр читает новый sklearn-бандл, переносит регрессоры в numpy и
ДОПОЛНИТЕЛЬНО обучает MLP-классификатор (256,128). Это не просто конвертация.
Scaler/fit — train 70%, порог — validation 15%, метрики — test 15%, seed=7.
В конце должны появиться "independent_test=" и "Сохранено:".
Метрики classifier_evaluation сохраняются внутри нового numpy-бандла.
Эта независимая оценка касается ТОЛЬКО классификатора: регрессоры уже обучены
на всех исходных данных. Старое F1=0.9982 с подбором порога на test не является
честным ориентиром. Новый результат может быть хуже — это нужно зафиксировать.

Если обучение или экспорт завершились ошибкой, остановитесь. Не принимайте
оставшийся старый файл за новый: проверьте сообщения и время изменения:

dir models\weights_v2.joblib
dir models\weights_v2_numpy.joblib

8. ПРОВЕРКА НОВОГО NUMPY-БАНДЛА И ИТОГОВАЯ ВЫДАЧА

.venv\Scripts\python.exe tests\check_numpy_only.py
.venv\Scripts\python.exe baseline_solution.py --nodes my_test\nodes.csv --lines my_test\lines.csv --weights models\weights_v2_numpy.joblib --out-dir predictions_new

Ожидается успешное завершение и сообщение "Готово:" с двумя файлами:
  predictions_new/pred_nodes.csv
  predictions_new/pred_lines.csv

Основной CLI проверяет формат результата и обнуляет выходы при флаге 0.
my_test входит в исходное обучение: это проверка запуска, не доказательство
точности. Полный набор тестов после смены весов может упасть на сравнении
с исторической выдачей. Разберите различия; не переписывайте эталоны вслепую.

Для настоящего теста замените пути nodes и lines на свои, например:
.venv\Scripts\python.exe baseline_solution.py --nodes "C:\GridTest\nodes.csv" --lines "C:\GridTest\lines.csv" --weights models\weights_v2_numpy.joblib --out-dir predictions_test
Пути C:\GridTest — примеры, таких файлов проект не создаёт.

Проверьте порядок и количество строк, отсутствие NaN/inf, единый флаг на опыт,
нули V/Delta/Imax/Izarg при флаге 0 и согласованность параллельных линий.
Входы для инференса могут не содержать целевых столбцов.
Для доказательства качества всей финальной модели нужен независимый набор,
не использованный ни в обучении регрессоров, ни при подборе порога. Готовой
полной команды независимой оценки финального numpy-бандла сейчас нет.

9. ЧТО СОХРАНИТЬ И ВЕРНУТЬ НА ОСНОВНОЙ ПК

- models/weights_v2.joblib и models/weights_v2_numpy.joblib;
- reports/stage4_results.json (и stage1_results.json, если запускали);
- reports/environment_training.txt, версию Python, команды и журналы запусков;
- результаты predictions_new/ и описание использованного набора данных.

Храните их отдельно от исходной версии до принятия решения о замене.
Для простого инференса на ещё одном ПК достаточно зависимостей из
requirements-inference.txt, numpy-весов, baseline_solution.py, каталога src/
и входных CSV. Joblib допускает выполнение кода при загрузке: только свои
или доверенные файлы, не случайные веса из интернета.

10. ТИПОВЫЕ ПРОБЛЕМЫ

FileNotFoundError с train_nodes/train_lines:
  Нет исходных данных, неверное имя или папка. Нужен HaKaToN/data/.

ModuleNotFoundError:
  Проверьте, что используете .venv\Scripts\python.exe и устанавливали пакеты
  через него, а src/ и scripts/ скопированы целиком.

Ошибка загрузки sklearn-весов / No module named '_loss':
  Несовместимые версии. Для запуска используйте numpy-бандл; для нового
  обучения создайте sklearn-веса заново и экспортируйте в том же окружении.

MemoryError / компьютер зависает:
  Остановите параллельные эксперименты, освободите ОЗУ или выберите ПК с
  большей памятью. Не уменьшайте набор незаметно и не выдавайте такой прогон
  за полное обучение. medium уменьшает сеть, но не объём загрузки CSV.

ConvergenceWarning:
  Проверьте число итераций и качество на отложенных данных. Предупреждение
  не доказывает ни поломку, ни достаточность обучения; не скрывайте его.

Ошибка входов или весов при основном запуске:
  Новые CSV не создаются, но старые в выбранной папке могут остаться.
  Используйте новый выходной каталог и проверьте код завершения/сообщение.

Нужна GNN или ускорение на GPU:
  Это отдельный эксперимент scripts/exp_stage3.py, не описанная выше модель.
  Данная инструкция намеренно не ставит torch/PyG и не обещает обучение GNN.
