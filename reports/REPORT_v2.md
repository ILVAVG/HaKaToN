Окружение: Python 3.10 venv `.venv310`; torch 2.14.1+cpu, torch-geometric 2.8.1,
scikit-learn 1.7.2, numpy 2.2.6, pandas 2.3.3. Seed фиксируется аргументами.
Основной пайплайн инференса — только sklearn/numpy/pandas/joblib (torch не нужен).

Все числа ниже измерены на реальных данных. Где не получилось — так и написано.

## 1. Быстрые победы (этап 1). Сравнение «до/после» на одном сплите
Сплит: GroupShuffleSplit 70/15/15 по ID_опыта, seed=42 (train=70000, val=15000,
test=15000). Оценка на test. «До» и «После» — одинаковый сплит.

| Метрика (test, валидные) | До (BEFORE) | После (AFTER + постобработка) |
|---|---|---|
| V MAE, кВ | 0.2122 | **0.1757** |
| V uniform R² по изменяющимся узлам | 0.96456 | 0.96499 |
| Delta MAE, ° | 0.02977 | **0.01500** |
| I_zarg MAE, % | 0.12853 | **0.11489** |
| I_max MAE, A (ном. I_доп) | 0.84735 | **0.79208** |
| Параллельные линии: макс. разброс I_zarg | 41.61% | **0.00%** |
| Флаг F1-macro (порог 0.5) | 0.99347 | 0.99347 (тот же HGB) |
| Флаг F1-macro (порог подобран на val = 0.29) | — | **0.99467** |

Что именно сделано:
1. **Параллельные линии**: 23 группы; усреднение внутри группы по (N_s,N_e,type,R,X,B,Kt).
   Разброс в группе стал строго 0 (критерий <0.05% выполнен). I_zarg MAE улучшился.
2. **Порог классификатора** подбирается на val под F1-macro (0.29 в этом сплите).
   На 15k test: confusion [[7383,39],[41,7537]] (строки true 0/1) →
   invalid→valid 39, valid→invalid 41. Раньше на 30k было 33 и 128;
   в пересчёте на 15k valid→invalid упало ~64 → 41.
3. **Дообучение MLP**: lr_init=5e-4, adaptive LR (factor 0.5), patience 40,
   max_iter 1500, batch 512. n_iter вырос с ~30–43 до 59–361 (в зависимости от цели);
   Delta/Izarg заметно точнее.
4. **Узел 1**: диагностирован как вырожденный (см. п.2).
5. **Честные метрики**: по узлам, классам напряжения, квинтилям нагрузки.

## 2. Узел 1 и метрика R² (объяснение, а не «исправление»)
- Узел 1: **99.76%** значений ровно 510.000 кВ; только 109 из 50085 опытов ниже
  509 кВ, все при sumPn 3882…4177. Это ступенчатая величина.
- Предсказание константы 510 даёт по узлу 1 R² ≈ −0.0017; наша модель после
  снапа — около −0.002. Отрицательный R² здесь неизбежен: дисперсия почти нулевая,
  а редкие просадки не выводятся из гладких признаков.
- Поэтому «честный» V uniform R² по изменяющимся узлам = **0.9645** (тянет вниз
  только узел 1). Медиана R² по узлам ≈ 0.9986. Если исключить вырожденный
  узел 1: **≈0.998** (по 3 seed: 0.9988 / 0.9971 / 0.9977). Критерий >0.99
  выполняется только с этим исключением — это оговорено, а не спрятано.
- Отдельно: R² по всем 35 узлам (с константами и смешением 500/220/110 кВ) ≈ 1.0 —
  это артефакт, как основную метрику его не используем.

## 4. Главный риск: данные упорядочены по ID (не iid)
ID опытов идут не 1…100000, а примерно до **170392** (100000 значений с пропусками).
Доля валидных по децилям ID:

| Дециль ID | valid_rate | средн. sumPn |
|---|---|---|
| 0–7 (до ~129k) | ~0.60–0.64 | ~3770–3800 |
| 8 (~129k–149k) | 0.088 | 4090 |
| 9 (>149k) | **0.000** | 4139 |

`corr(ID, regime_valid) = −0.337`, `corr(ID, sumPn) = +0.284`.
То есть данные, похоже, генерировались с ростом нагрузки к концу набора; поздние
ID почти все невалидны. Последствия:
- случайный сплит **оптимистичен** для скрытого теста, если тест брался «с конца»;
- блочный сплит по ID даёт F1 0.8735 — оценка риска сдвига;
- экстраполяция на тяжёлые режимы не проверяема (нет валидных).
Это надо донести до организаторов (вопрос о распределении скрытого теста).

## 5. Физика (этап 2) — не воспроизводится
Подробно в `physics_check.md`. Кратко:

## 7. Сабмит (этап 5)
- Финальные регрессоры обучены на **всех** опытах (100k, 50085 валидных) конфигом
  AFTER и сохранены в `weights_v2.joblib` (sklearn 1.7.2, 4.8 МБ).
- **Проблема версий**: `weights_v2.joblib` НЕ грузится в sklearn 1.9 (Python 3.14):
  `ModuleNotFoundError: No module named '_loss'` (внутренний Cython-модуль sklearn
  переименован между версиями). Это блокер для проверяющей машины с другим sklearn.
- **Решение**: экспорт в plain-numpy бандл `weights_v2_numpy.joblib` (1.67 МБ,
  только numpy-массивы + метаданные; никаких классов sklearn). Внутри: веса MLP
  (V/Delta/Izarg) + MLP-классификатор флага (256,128) + скалеры + константы/снапы.
  Инференс реализован в `grid_mlp.np_forward_reg/np_forward_prob`. Экспорт:
  `export_numpy_bundle.py`.
- **Проверка кросс-версионности**: одинаковые предсказания на Python 3.14/sklearn 1.9
  и Python 3.10/sklearn 1.7 (макс. расхождение ~1e-13); совпадают и с sklearn-бандлом.
- `baseline_solution.py` по умолчанию берёт `weights_v2_numpy.joblib`; если его нет —
  `weights_v2.joblib`. После доработки ошибка загрузки/отсутствие весов завершает
  процесс с кодом 1; выдача заглушки удалена.
- Исторический MLP-классификатор флага: F1-macro = **0.9982**, split seed=7,
  порог 0.22. **Оценка оптимистична:** экспортёр подбирал порог на той же te,
  где печатал F1. Это не независимый holdout; устойчивая оценка — 3-seed HGB
  из п.3 (другая модель). Экспортёр исправлен, но веса не переобучались.
- Проверено: `python baseline_solution.py --nodes my_test/nodes.csv --lines my_test/lines.csv --out-dir predictions`
  проходит валидацию формата; `predictions/` перегенерирован финальным бандлом.
- Проверена **робастность к скрытому тесту без целевых колонок** (вход только
  `ID_опыта, Номер, U_ном, P_н, Q_н, P_г` и геометрия линий) — работает, предсказания
  идентичны полной схеме.
- Для невалидных (предсказанный флаг 0) выдаются нули V/Delta/Imax/Izarg.
- Параллельные линии в финальной выдаче согласованы (разброс 0, проверено на 8/9).
- my_test (он входит в train => оптимистично, только sanity): V MAE 0.164,
  Delta 0.0069, I_zarg 0.0424, I_max 0.2625, флаг accuracy 1.0.

Замечание: в `predictions/` лежат предсказания на my_test (других тестовых файлов
в папке нет). Для скрытого теста запускать baseline_solution.py на его файлах.

## 9. Ограничения (что не так)
1. **Сдвиг по ID**: случайный holdout оптимистичен; блочный тест F1 0.87. Скрытый
   тест может быть из другого распределения.
2. **Узел 1** вырожден; R² по нему отрицателен, «исправления» нет (только объяснение).
3. **Граница/тяжёлые режимы**: ошибка V растёт до 0.28+ кВ; экстраполяцию
   проверить нельзя (нет валидных).
4. **Физика не подтверждена**; solver не реализован и не проверен.
5. **GNN недоучена** (CPU); сравнение с sklearn не в пользу GNN.
6. **I_max** восстанавливается через номинальный I_доп (истинный I_доп иногда даёт
   хуже — связка хрупкая). Если в тесте I_доп нет — только номинал.
7. **Q_н=k·P_н** проверено на train; если в тесте иначе — потеря информации.
8. Один набор гиперпараметров; без байесовского поиска; 3 seed — минимум.
9. Регрессия учится только на валидных; ошибки флага (особенно valid→invalid и
   invalid→valid) напрямую бьют по итоговым метрикам.
10. R² по всем узлам (~1.0) — артефакт, не показатель.

поэтому переобучение, новый экспорт и повторная оценка точности на случайных,
блочных и тяжёлых режимах не выполнялись. Исходные веса сохранены.

- Numpy-инференс больше не импортирует sklearn. Добавлен отдельный
  `requirements-inference.txt`; torch/PyG для запуска не нужны.
- Удалена успешная заглушка при потере/ошибке весов: код завершения 1,
  новые CSV не создаются. Старые CSV при ошибке остаются и могут быть устаревшими.
- `grid_validation.py` проверяет схему, ключи, конечность чисел, комплектность
  опытов, стабильность геометрии и размерности numpy-весов. Проверки не зависят
  от `assert` и остаются включёнными с `python -O`.
- Узел 999 необязателен, его генерация игнорируется. Целевые столбцы не влияют
  на инференс. Сохранены порядок строк, усреднение параллельных линий и нули
  для предсказанного невалидного режима. Сигмоида защищена от переполнения.
- В экспортёре scaler/fit используют только train, порог — только val,
  метрики — только test. Оценка относится только к классификатору:
  исходные регрессоры обучены на всех данных. Веса после оценки не дообучаются.
- В этапе 4 прежние условные метрики сохранены, добавлены
  `regression_conditional` и `regression_submitted` (с обнулением по флагу)
  на истинно валидных опытах. Если их нет, результат `null`, не нулевая ошибка.
- Проверено на Python 3.12: `unittest discover -s tests -v` — 21 тест, OK;
  тот же набор с `-O` — 21 тест, OK; `compileall` — без ошибок.
  Включены отдельный процесс с запретом sklearn, реальные CLI-запуски,
  повреждённые/отсутствующие веса, совпадение с выдачей до правок,
  независимость обучения/порога от тестовых меток, единственный валидный опыт,
  постоянная нагрузка и сводки с неопределёнными метриками.
  Независимый исследователь прочитал код и обнаружил два граничных дефекта
  оценки (постоянная нагрузка и сводка с null); оба исправлены и покрыты тестами.

Ограничения раздела 9 не устранены: сдвиг по ID, тяжёлые режимы, узел 1,
неподтверждённая физика и недообученная GNN. Старые веса не содержат эталонной
топологии: проверяется неизменность геометрии между опытами, но не её точное
совпадение с обучающей сетью. Q_н не используется моделью как независимый признак.
